# 离线 HTML 交付

用于 Session 与 Project 的默认交接文档。本参考只负责输出，不扩大交接范围、权限或取证工作。

## 一份文件就能阅读

使用 UTF-8 和准确的 `<html lang>`；包括 viewport、语义化标题、必要的段落、列表、表格和 `<pre><code>`。正文必须包含接手所需的背景、版本/状态、关键证据、操作步骤和第一项行动。外部链接用于取代码、补充资料或溯源，不能代替关键说明。

在已有环境允许时从同一 Markdown 或结构化事实源生成 HTML。可使用包内 [assets/handoff-template.html](../assets/handoff-template.html) 的离线样式与结构，把其中的语言、标题和正文槽位替换为最终内容；模板不是已完成的文档，也不要求使用特定渲染工具。保留自然段与标题层级，不能把 Markdown 源码每一行固化为 HTML 换行。不要为正文和列表额外设置窄行宽。

CSS 内联，使用系统字体；不从 CDN 获取样式、字体、脚本或公式渲染器。核心内容不依赖 JavaScript、浏览器存储或网络 API。复制按钮和目录等增强功能可以存在，但必须支持键盘，脚本禁用后文字与代码仍可读取。代码/日志允许局部横向滚动，页面整体不应溢出。

## 必要的图文信息

- 结构、流程、状态关系或界面问题若仅靠文字不易接手，加入对应的架构/流程图、状态图或实际截图；图必须帮助理解当前任务，不能只起装饰作用。无需可视化的小型 Session 可只用文字与表格。
- 截图等栅格图片使用内嵌 data URI；图示可使用无外部依赖的内联 SVG。不得留下发送者本机绝对路径、未随附的图片文件、远程图片或需要在线运行的 Mermaid 源码作为唯一图示。不要把不可读的截图当作正文替代品。
- 图片提供有效 alt；SVG 提供 title/desc 与可访问名称。图注说明对象、版本/时间、来源和适用范围，正文或表格保留图中关键信息，颜色不能是唯一状态信号。
- 只使用有权分享且已去除敏感信息的素材。没有可访问的实际截图时，说明缺口或绘制明确标识的结构示意，不能伪造运行截图、数据或成功证据。
- 数学内容使用构建时渲染并内嵌的 MathML/KaTeX 结果，不依赖 CDN。公式未正确渲染时应修复后交付，不能把源码出现当作公式展示通过。

## 阅读独立与项目运行

“HTML 可独立阅读”指文件本身具有理解与接手所需的内容，和运行项目所需依赖的可获得性是两个验收条件。文档中的代码与大数据可按主流程通过 GitHub 等合法入口获取，必须说明网络、权限和环境前提；不用把整个仓库塞进 HTML。不能因为离线文档打开成功，就声称项目已可运行。

同机模式可在说明中引用实际本地工作区，但该路径不是 HTML 的渲染依赖。分享模式使用接收者可访问的固定 GitHub 版本与相对路径。Markdown、源图和其他审计资料可以另附，但读取 HTML 正文不能要求先取得它们。

## 交付检查

1. 核对 HTML 与 Markdown 的事实、命令、图示含义、结论和限制相同，且全部占位符已经替换。
2. 只复制 HTML 到空目录，禁用 JavaScript 并阻断外网后打开；正文、图表和图注必须完整，没有丢图、需要登录的正文或外部资源请求。
3. 检查手机与桌面宽度，正文自然折行，没有异常留白或页面横向溢出；长代码与表格只局部滚动。检查打印视图的裁切与分页。
4. 检查图文替代、标题层级、可见焦点和必要的交互。若缺少浏览器能力，只报告实际完成的结构核验，不称为视觉通过。
5. 在最终回复中链接主 HTML 与 Markdown，并简短说明实际完成的检查。不要把浏览器打开文档、文档生成或结构检查当作项目运行成功。
